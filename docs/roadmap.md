# Roadmap

Flow Factory ships in numbered releases. Each release has to be useful to an
engineer on its own, so scope is never cut down to the least that passes a
test.

## What MVP 1 gives you today

MVP 1 carries one flow from an unclear idea to a merged, closed-out change.

- **macOS and Claude Code.** The supported machine and the supported agentic
  system.
- **The four stages.** Discover, Define, Decompose and Deliver, with the
  skills that serve each of them (`skills.md`).
- **The tracker.** Markdown issues and candidates inside your project, with
  statuses, dependencies, acceptance criteria and close-out. You read it
  through a skill that prints it, not through a separate interface.
- **The installer.** One run places the skills and the tracker rules on your
  machine, and the work folder and the settings file in your project.

A finished flow leaves a discovery and decision trail, a bounded piece of work
with acceptance criteria, executable work items with their dependencies, an
implementation on its own branch, verification evidence against those
criteria, a merged change, and a closed-out tracker item.

## Deferred to a later release

- a broader catalogue of skills;
- project-specific domain skills;
- starting your project's app, and live verification through a running app;
- Windows support;
- GitHub Copilot CLI support;
- VS Code Copilot support;
- git hosting other than GitHub, and what "merged" means there;
- Jira and other external trackers beyond a documented manual path;
- automatic prioritization of the backlog; and
- automatic migration of an existing project tracker.

## Not planned

The factory has a small number of users we can reach directly, so none of this
earns its cost:

- a user interface beyond the skill that prints the tracker;
- a hosted service or central database;
- organization-wide dashboards and analytics; and
- multi-user permissions and enterprise administration.
